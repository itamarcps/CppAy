# Testing

## Public suite

```sh
python -m pip install -r requirements-dev.txt
cmake --preset linux-release
cmake --build --preset linux-release --parallel
ctest --preset linux-release
```

A fresh checkout runs eight checks without local music, Pascal, reference
archives or downloaded SDKs. Controller/session checks do not require an audio
device; the session check additionally verifies audible resume when one exists.
Allow about fifteen seconds for the actual ten-second checkpoint/forced-kill
restart check. Generated files go into the build directory.

- `core_behavior`: deterministic/concurrent rendering, odd/single-frame streaming,
  checkpoints, bounds, cancellation, profile validation and silence.
- `comparator_behavior`: WAV parsing and PCM/event comparison behavior.
- `integration_prepare` / `integration_render`: fresh build-generated WAV for
  the newly authored 64-row `integration.pt3` track.
- `qt_controller_behavior`: cursor/export consistency, cancellation, overwrite
  refusal, playlists, 3,000-file metadata import and superseded loads. Also checks
  saved logarithmic volume, migration of old linear settings without changing
  audible gain, and actual sink gain on creation/update when an audio device exists.
- `session_crash_resume`: actual periodic save, forced process kill and restored
  ordering, active song, selection, cursor, settings and play/pause intent.
- `independent_source_fixtures`: twelve immutable independent expected PCM/event
  fixtures, plus timing override and format bounds checks.
- `streaming_playback_behavior`: bounded queues, PCM/seek consistency, independent
  three/six voice taps, silence and rising-edge alignment at arbitrary cursors,
  including notes whose periods exceed the displayed scope window.

The build-generated integration WAV is a consistency reference from the same
engine, **not an independent golden**. Independent compatibility evidence comes
from the committed source-oracle fixtures; their hashes are checked before use
and they are never regenerated by ordinary tests.

## Core sanitizers

```sh
cmake --preset core-debug
cmake --build --preset core-debug --parallel
ctest --preset core-debug
```

This omits Qt and runs the core/comparator/integration/independent fixture checks
with AddressSanitizer and UndefinedBehaviorSanitizer. If your host preloads a
library that precedes the ASan runtime, unset `LD_PRELOAD` for the test command.

## Optional private golden comparison

Obtain your own permission to use the original pair and place it at
`samples/Flexo02.pt3` and `samples/Flexo02.wav`. They are deliberately ignored.

```sh
cmake --preset linux-release -DAYPLAYER_GOLDEN_TESTS=ON
cmake --build --preset linux-release --parallel
ctest --preset linux-release
```

This adds full render/PCM comparison with no alignment, trimming or gain
correction. Missing files produce a clear configure error. Disable the option
again with `-DAYPLAYER_GOLDEN_TESTS=OFF` for a public-checkout-only build.

## Desktop and Windows checks

On an actual desktop, the player has diagnostic `--smoke-test`,
`--layout-smoke-test` and `--stream-smoke-test` modes. Run them in a fresh working
folder; outputs are written under `evidence/` there. Inputs must include a track
longer than 25 seconds and a TurboSound fixture for all checks. The public
`tests/fixtures/integration.pt3` and `tests/fixtures/native-ts.pt3` work.

```sh
mkdir -p build/manual-review
cd build/manual-review
../C++Ay --layout-smoke-test ../../tests/fixtures/integration.pt3 ../../tests/fixtures/native-ts.pt3
```

The full transport smoke exercises an audio device, cursor dragging, compact
mixer, List tools action and export during playback. Its export refuses existing
output files, so remove only your prior generated `evidence/gui-export.wav`
before repeating it. Use isolated XDG configuration/data paths for manual
checks if you do not want to change your regular player session.

`tools/build_windows.sh --verify` additionally checks the deployed MinGW binaries
under an isolated Wine prefix. It uses the private golden pair when present,
otherwise the public integration fixture and a Windows CLI-render consistency
reference; the twelve independent fixtures are always checked. Wine's audio
endpoint GUID workaround is confined to that test prefix. A Wine pass does not
replace physical Windows device testing.
